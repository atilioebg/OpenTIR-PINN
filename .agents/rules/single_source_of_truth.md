# SINGLE SOURCE OF TRUTH (SSoT) FOR DATASET FACTS

## Why this rule exists
Between v1.0 and v1.1.1, hand-typed numbers drifted out of sync with the generated data. Examples include 16,204 vs 17,204 samples, 5,000 vs 5,500 training samples, 25/5 vs 20/10 atmospheres, albite vs anorthite, PWV < 0.3 vs 0.21–1.70 g/cm², and an unsupported "−79.3%". Each of these is a Reviewer #2 rejection vector. The only defence is to stop hand-typing numbers.

## Mandatory behaviour
1. **Canonical file:** `data/dataset_facts.json`, generated by `scripts/build_dataset_facts.py` *only* from the artefacts: catalogs, split manifests, `lut_catalog.csv`, and `.pt` tensors. Never edit it by hand.
2. **Before writing any dataset number** (counts, spectra, classes, atmospheres, PWV, temperature grid, NEΔT, augmentation, golden target identity, shapes) in any file (README, DATA_DICTIONARY, DASHBOARD_USER_GUIDE, dashboard code, `clarification.md`, `main.tex`, `paper_log/*`), read it from `dataset_facts.json`. Code (the dashboard and packager) must `json.load` the manifest instead of hardcoding literals.
3. **After any change to data generation** (library, split, LUTs, synthesizer), run:
   `python scripts/build_dataset_facts.py` and then `python scripts/validate_dataset_integrity.py`.
   Do not report a dataset change as finished while the validator has a FAIL. Do not quote numbers while `python scripts/build_dataset_facts.py --check` returns STALE.
4. **Numbers that are not in the manifest** (model metrics, benchmark results) must cite their CSV/JSON source file. If no source exists, write `[SOURCE NEEDED: ...]`; never fill the gap with a plausible number.
5. **Plain-language summaries** must not mix counts with noise. Write "N = targets × atmospheres × temperatures; each sample carries NEΔT noise". Never write "N = (…) + noise".
6. **Conflict resolution:** if a document disagrees with the manifest, the manifest wins. Fix the document and log the correction in `clarification.md`.
7. **Grounding precedence (PI decision, 06/11/2026):** the grounding set is the reference truth: `data/dataset_facts.json` (numbers), `docs/perturbation_model_error_sources.md`, `docs/noise_vs_error_budget.md`, `docs/modtran_downwelling_decision_v112.md`, `docs/dataset_validation_protocol.md`, `docs/PIPELINE_README.md` and `clarification.md` Entries >= 34. It overrides older plans, reports and audits (e.g. the peer-review report, `project_status_audit.md`, `implementation_plan_scientific_paper.md`). If an older document recommends something that contradicts the grounding set (e.g. trainer-side noise, ungrounded jitter), follow the grounding set and flag the conflict.
8. **Void results:** every result of the 04/11 training campaign (benchmarks, CV, LOCO, quarantine matrix, Bland-Altman, ablations, Optuna hyperparameters) was produced on the corrupted dataset and is void. Never quote or reuse it; regenerate in the new campaign.
